# --- Data integrity rules ---
When a SQL query returns 0 rows or an empty result set, always respond with: 'No records found for your query.' Never fabricate, invent, or hallucinate data that was not returned by the database.
Never generate example rows, placeholder data, or sample records. Only show data that actually came from executing the SQL query against the database.
If a filter like WHERE centreid = X returns no results, do not invent projects or records. Say: 'No records found for your query.'

# --- Organisation context ---
This is a NIFT (National Institute of Fashion Technology) project management system. NIFT is an Indian government fashion institute with multiple campuses across India called centres.
Each NIFT centre is identified by a centreid and has a centrename. For example centreid=1 is BENGALURU, centreid=2 is BHOPAL, centreid=9 is KOZHIKODE (KNR).
centrestatus='A' in centre_master means the centre is Active.

# --- centre_master table ---
centre_master stores information about all NIFT centres (campuses) across India.
Columns in centre_master: centreid (unique ID), centrecode (short code like 01, 02), centrename (city name), nodal_officer1 (faculty in charge), fulladdress, contactno, cemailid (centre email), centrestatus (A=Active).
asset_ccode in centre_master is a two-letter code for the centre (e.g. BE=Bengaluru, BH=Bhopal, BU=Bhubaneswar).
When users ask about a centre by name like 'Chennai' or 'Kozhikode', look up the centreid from centre_master using centrename.

# --- project_master table ---
project_master is the main table for all NIFT consultancy and training projects.
projectid in project_master is a unique alphanumeric project code like NIFT/KNR/PRO/10 or HO01.
projectname is the full name of the project.
deliverables describes what the project will produce or deliver.
clientid in project_master links to project_client_master to get the client name.
ref_file_no is the internal file reference number for the project.
startingdate is when the project started.
expecteddate is the expected completion date of the project.
duration_month and duration_days together represent the total duration of the project.
duration_years is the number of years the project spans.
cost in project_master is the total project value in Indian Rupees (INR) in thousands (i.e. cost=2103.68 means Rs. 21,03,680).
status in project_master has three values: ACTIVE means the project is currently ongoing, NON-ACTIVE means the project is inactive or on hold, NA means status is not applicable.
creationdate is when the project record was created in the system.
usrname is the login username of the person who created the project record.

# --- project_client_master table ---
project_client_master stores details of clients who commission projects from NIFT.
clientid is the unique client identifier.
clientname is the name of the client organisation.
contact1, designation1, mobile1, email1 are the primary contact details.
To get the client name for a project, join project_master.clientid = project_client_master.clientid.

# --- project_member_details table ---
project_member_details stores the team members assigned to each project.
mem_type_cat_pi_pdt_pit_paas is the role of the member: PI/PC means Principal Investigator or Project Coordinator.
mem_cms_usr_categ is the category: Faculty or Staff.
mem_centreid is the centre the member belongs to.
mem_facid_empcode is the faculty or employee code.
mem_name is the full name of the project member.
To find members of a project, join project_member_details.projectid = project_master.projectid.

# --- project_plan table ---
project_plan stores the planned activities and milestones for each project.
project_sno in project_plan is a foreign key to project_master.sno (not projectid).
target_date_month and target_date_year indicate when the planned activity should be completed.
plan_deliverables describes what should be delivered.
activities_plan describes the planned activities.
status in project_plan: Active or ACTIVE means the plan item is active.

# --- project_qpr table ---
project_qpr stores Quarterly Progress Reports (QPR) for projects.
QPR stands for Quarterly Progress Report — submitted every quarter to track project progress.
qpr_yr is the year of the QPR.
qpr_quarter is the quarter period like Oct-Dec, Jan-Mar, Apr-Jun, Jul-Sep.
proj_value is the total project value in the QPR.
amt_recev_till_qtr is the total amount received from client up to this quarter.
exp_occ_upto_last_qtr is expenditure incurred up to the previous quarter.
exp_occ_this_qtr is expenditure incurred in the current quarter.
bal_amt is the balance amount remaining.
proj_coordinator is the name of the project coordinator.

# --- project_receivable_receipt table ---
project_receivable_receipt stores payment receipts received from clients for projects.
project_sno in this table is a foreign key to project_master.sno.
recipt_type describes the payment type like Part Payment or Full Payment.
total_rec_amount is the total receivable amount.
rec_amount is the amount received in this receipt.
receipt_no is the receipt or cheque number.
receipt_mode is how payment was made: Online, DD (Demand Draft), Cheque.
receipt_date is when the payment was received.

# --- project_expenditure_details table ---
project_expenditure_details stores expenses incurred on each project.
project_sno is a foreign key to project_master.sno.
expenditure_amount is the amount spent in Indian Rupees.
expenditure_date is when the expense was incurred.
exp_ref_no is the reference number for the expenditure.

# --- project_bal_details table ---
project_bal_details stores the balance and financial closure details of projects.
project column is a foreign key to project_master.sno.
pro_amount is the total project sanctioned amount.
rec_amount is the total amount received from the client.
exp_incurred is the total expenditure incurred.
income is the net income (rec_amount - exp_incurred).
status in project_bal_details describes financial status: 'Physically Completed and Financially Closed' means the project is fully done and accounts are closed.
utilisation_certificate indicates whether a utilisation certificate has been submitted.

# --- project_review table ---
project_review stores review comments and remarks on projects from different stakeholders.
project_sno is a foreign key to project_master.sno.
activity_plan describes the planned activity being reviewed.
activity_complets describes what was actually completed.
comp_date is the completion date of the activity.
remarks_coodinator is the remark from the project coordinator.
remarks_director is the remark from the NIFT centre director.
remarks_hproject is the remark from the Head of Projects at HO (Head Office).
remarks_dg is the remark from the Director General of NIFT.
review_quarter and review_year indicate which quarter and year the review covers.

# --- Dept_Master table ---
Dept_Master stores the academic departments at NIFT.
deptid is the unique department ID.
deptname is the department name. Departments include Fashion Design, Textile Design, Knitwear Design, Accessory Design, Leather Design, Fashion Communication, Foundation Programme Design, Master of Design Space.
deptstatus='A' means the department is Active.

# --- Table relationships ---
project_master joins to centre_master on centreid column.
project_master joins to project_client_master on clientid column.
project_member_details joins to project_master on projectid column.
project_plan.project_sno joins to project_master.sno (not projectid).
project_qpr joins to project_master using both centreid and projectid columns.
project_receivable_receipt.project_sno joins to project_master.sno.
project_expenditure_details.project_sno joins to project_master.sno.
project_bal_details.project joins to project_master.sno.
project_review.project_sno joins to project_master.sno.

# --- Common query patterns ---
To list projects for a centre, use: SELECT * FROM dbo.project_master WHERE centreid = <id>
To get centre name from centre ID, use: SELECT centrename FROM dbo.centre_master WHERE centreid = <id>
To find project with client name, join project_master with project_client_master on clientid.
To get total project value for a centre, use: SELECT SUM(cost) FROM dbo.project_master WHERE centreid = <id>
To count active projects, use: SELECT COUNT(*) FROM dbo.project_master WHERE status = 'ACTIVE'
To find all members of a project, join project_member_details with project_master on projectid.
When searching project by name use LIKE operator with % wildcards.
Always use dbo. schema prefix when querying tables, e.g. dbo.project_master not just project_master.

# --- Primary key clarification ---
sno in project_master is the auto-increment integer primary key and is the actual project identifier used by all other tables as a foreign key.
projectid in project_master is a human-readable project code like NIFT/KNR/PRO/10 and is NOT used as a foreign key by other tables.
When joining project_plan, project_receivable_receipt, project_expenditure_details, project_bal_details, or project_review to project_master, always join on project_master.sno — never on project_master.projectid.
project_plan.project_sno = project_master.sno (the serial number, not the project code).
project_receivable_receipt.project_sno = project_master.sno (the serial number, not the project code).
project_expenditure_details.project_sno = project_master.sno (the serial number, not the project code).
project_bal_details.project = project_master.sno (the serial number, not the project code).
project_review.project_sno = project_master.sno (the serial number, not the project code).
To get receipts for a project by project code, first find the sno from project_master where projectid = '<code>', then use that sno to query project_receivable_receipt.
To get expenditure for a project by project code, first find the sno from project_master where projectid = '<code>', then use that sno to query project_expenditure_details.
